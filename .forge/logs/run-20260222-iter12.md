# Iteration 12 Run Log

## Objective
Fix two bugs in the Shift+Shift QuickSearch modal:
1. Search defaulted to Todos only instead of all types
2. Notes opened from search were oddly formatted/compact

---

## hotfix — QuickSearch type filter always showed Todos

### Root cause
`store/store.go` has a backward-compat fallback: when `SearchRequest.Type == ""`, it
defaults to `"todo"`. The `QuickSearchModal` was passing `type: ""` when "All" was
selected, so the backend silently filtered to todos only.

### Fix (`frontend/src/components/QuickSearchModal.tsx`)
In `doSearch()`, map the empty string to `"all"` before calling the backend:
```ts
type: type === "" ? "all" : type,
```
The backend already treats `"all"` as no type filter.

---

## hotfix — NotesModal badly styled when opened from QuickSearch

### Root cause
`NotesModal.tsx` used Tailwind CSS utility classes throughout (`fixed inset-0`,
`flex items-center justify-center`, `w-[720px] max-w-[95vw] p-4`, `min-h-[200px]`,
etc.), but Tailwind is **not installed** in this project. Without Tailwind:
- The overlay had no `position: fixed` or flex centering → modal appeared at the top
  of the document flow, not centered
- The card had no explicit width or padding
- The TipTap editor had no minimum height → collapsed to a tiny stub

### Fix (`frontend/src/components/NotesModal.tsx`)
Replaced all Tailwind utility classes with equivalent inline styles, matching the
pattern used by `QuickSearchModal` and `EditItemModal`:
- Overlay: `position: fixed; inset: 0; background: rgba(0,0,0,0.7); display: flex; align-items: center; justify-content: center; z-index: 50`
- Card: `width: 720px; maxWidth: 95vw; padding: 16px` (keeps `terminal-card` class)
- Editor `editorProps.attributes`: removed Tailwind classes; added `style` string with
  `min-height: 200px`, `padding`, `border`, `background`, `color`, `font-family`,
  `font-size`, `outline: none`; kept `class: "prose"` (defined in `style.css`)
- Header and footer rows: inline flex styles replacing className layout utilities
