# Iteration 5 Run Log

## Objective
Fix chat not having access to vault data. Claude was unable to answer "show me the last 10 items" because the blind FTS5 pre-search found nothing.

## Root Cause
`SendChatMessage` ran `Store.Search(userMessage, PageSize=10)` and injected the JSON results into the user message. For natural language queries like "show me the last 10 items", FTS5 finds zero keyword matches. Claude correctly reported no results.

## Solution: Anthropic Tool Use
Replaced pre-search with Claude-initiated tool calls via the Anthropic API tool use feature.

### TASK-20260222-011 — Tool-use agentic loop

**`chat/models.go`** — Added `BridgeStore` interface:
```go
type BridgeStore interface {
    Search(ctx context.Context, req store.SearchRequest) ([]store.Item, error)
    GetItem(ctx context.Context, id int64) (*store.Item, error)
}
```

**`chat/bridge.go`** — Major rewrite:
- `BridgeRequest.SearchCtx` removed; `BridgeRequest.Store BridgeStore` added
- `defaultMaxTokens` bumped from 1024 → 2048 (needed for tool-use reasoning)
- HTTP timeout bumped 60s → 90s (multi-turn loop)
- Tool definition: `search_vault` with query, type, statuses, priorities, projects, contexts, tags, sort_by, sort_dir, limit
- `Send()` is now an agentic loop (max 5 iterations):
  - stop_reason=end_turn: extract text, parse action, return
  - stop_reason=tool_use: execute tools via store, append tool_result, continue
- `callAPI()`: extracted helper for single HTTP round-trip
- `executeSearchVault()`: builds `store.SearchRequest`, calls store, returns slim JSON (notes truncated at 400 chars)
- `extractTextFromContent()`: joins text blocks from structured content
- System prompt updated: instructs Claude to use search_vault tool

**`app.go`**:
