## Description
Design and implement a reusable conversion service that accepts raw text/Markdown (and eventually other formats) and outputs the TipTap-compatible HTML + metadata Nanite expects. The service should expose both Go helpers and a CLI/API entry point so file imports, chat actions, and future bulk tools can normalize content consistently. Follow-up: add heuristic/intelligent classification (todo vs note, inferred tags/projects) that CLI imports can opt into.

## Requirements
- Define an interface (package or service) that converts UTF-8 text to sanitized TipTap HTML, including wikilink detection and newline handling identical to the editor.
- Provide a CLI-accessible command (e.g., `nanite convert --file foo.md`) for testing/debugging once implemented.
- Document how agent pipelines should request conversion/intelligence so CLI imports can switch from "raw text" to "rich conversion" without breaking existing scripts.

## Notes
- Unblocks BACKLOG-20260222-007 (file import auto-convert) and future GUI features that need server-side conversions.
- Intelligence/post-processing can piggyback on the same package when the ML/RAG components are ready.
## Follow-ups
- Historical context cache: persist dated snapshots (e.g., daily/weekly) so agents can analyze trends without recomputing queries. Tackle when RAG/time-series use cases appear.
- Per-entity context cache: break snapshots into vault-/project-level JSON files for faster targeted lookups. Useful once specific agent flows require narrow slices of context.
