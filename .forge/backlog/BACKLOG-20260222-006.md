## Description
Establish a consistent CLI experience so future GUI/chat flows can rely on it. Choose and wire up the command framework (enhanced `flag`, Cobra, or urfave/cli), add `nanite help`/`nanite version`, and introduce new top-level verbs (`nanite add`, `nanite list`, `nanite show`, `nanite context`, `nanite import`, etc.) as no-op stubs that print "coming soon" JSON payloads. This lets the GUI and internal agents start composing flows while the API layer firms up.

## Requirements
- Decide on framework vs custom dispatcher; document tradeoffs in `docs/CLI.md`.
- Stub commands must parse flags/positional args and return deterministic JSON/exit codes even before persistence logic exists.
- Preserve legacy aliases (`push`, `get`, `inbox`, etc.) until the new flow is ready; add warnings directing users to the new verbs.

## Notes
- Once backend APIs exist, convert each stub into a real implementation without changing the public contract.
- Coordinate with chat addon so both humans and agents see the same help text.
