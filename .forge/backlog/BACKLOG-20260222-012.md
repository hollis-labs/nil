## Description
When editing an existing item that contains characters like `:`, `/`, or `|` in the title, pressing Escape inside EditItemModal triggers the "save on close" prompt even though the user hasn't changed anything. The dirty-check currently compares the `line` state against `initialValuesRef.current.line` verbatim, so some part of the render path is likely normalizing/escaping the text before it lands in the input. Need to track down where the difference is introduced and normalize titles (or stop the extra encoding) so the close-behavior logic doesn't think there are changes.

## Notes
- Hypothesis: title strings are being HTML-encoded for display, so `line` holds the encoded version while `initial` holds the raw DB value.
- Investigate ItemTitleInput and any helpers that transform the text before comparing in `isDirty()`.
- Accept/Cancel UX should only prompt when actual fields changed.
