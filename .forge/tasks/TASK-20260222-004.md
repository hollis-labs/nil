## Description
Implement the full Action Proposal → Approval → Execute flow in `chat/actions.go`. This ties together: persisting the proposal, executing it via `store.Store` methods, writing audit records, and handling dry-run mode.

## Paths
- `chat/actions.go` (new)

## Acceptance Criteria
- [ ] `ActionRunner.Propose(ctx, proposal ActionProposal) (int64, error)` — persists to `action_proposals`, writes audit(outcome=proposed), returns proposal ID
- [ ] `ActionRunner.Approve(ctx, proposalID int64, vaultStore *store.Store, dryRun bool) (*ActionResult, error)` — executes if not dry_run; updates proposal status; writes audit(outcome=executed|dry_run)
- [ ] `ActionRunner.Deny(ctx, proposalID int64) error` — updates proposal status; writes audit(outcome=denied)
- [ ] `create` action: calls `vaultStore.CreateItem`
- [ ] `update` action: calls `vaultStore.UpdateItem`
- [ ] `delete` action: calls `vaultStore.DeleteItem`
- [ ] Vault capability check before execute (return error if vault doesn't allow write/delete)
- [ ] Dry-run: audit outcome=`dry_run`, proposal status=`dry_run`, no store call
- [ ] `go build .` passes

## Verification
```bash
go build .
```

## Notes
- Vault caps come from `config.ChatConfig.VaultCaps[vaultID]`
- Always check caps before any mutation; if missing, default to `{read:true, write:false, delete:false}`
