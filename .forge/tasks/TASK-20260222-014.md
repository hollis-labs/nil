## Description
Add three new tools to the Bridge to give Claude richer data access without always needing full-text search.

- **`get_item`** — fetch one item by ID with complete notes (search truncates at 400 chars). Used when Claude needs full note content for synthesis.
- **`list_taxonomy`** — return all projects, contexts, and tags with item counts. Used at session start or when Claude needs to understand vault structure.
- **`get_vault_stats`** — aggregate counts: items by type/status/section, overdue count, inbox count, this-week completions. Used for weekly reviews and progress summaries.

## Acceptance Criteria
- [ ] `get_item` tool: input `{id: integer}`, calls `store.GetItem()`, returns full item JSON including `notes_text`
- [ ] `list_taxonomy` tool: no input; queries projects, contexts, tags with item counts; returns `{projects: [{name, count}], contexts: [...], tags: [...]}`
- [ ] `get_vault_stats` tool: no input; returns `{total, open, completed, archived, overdue, inbox, notes, todos, by_section: {now, soon, anytime}}`
- [ ] All three tools registered in `searchVaultTool()` → rename enclosing func to `buildTools()`, return `[]toolDef`
- [ ] `BridgeStore` interface extended with `GetItem`, `GetFilterValues` (or a new `GetStats` method)
- [ ] Tool descriptions written for Claude: when to use each, what fields are returned
- [ ] System prompt updated to mention `list_taxonomy` as recommended first call for "what's in my vault" queries
- [ ] `get_vault_stats` implementation queries store directly (may need new `GetStats` method on Store)
- [ ] `go build .` + `npx tsc --noEmit` clean
